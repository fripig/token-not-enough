## Context

Ticket titles are picked from per-language title pools (`pool.<stack>.<1–5|trap|research|inc>` in `public/js/i18n/zh-TW.js` and `en.js`, exposed through `STACKS[k].pool` / `poolOf`). Every language has the same pool sizes and order, so the same random draw picks the corresponding title. Today `makeIssue` keeps only the finished string in `title`; research tickets keep their part titles as strings in `parts`; `splitResearch` copies those strings into the parts' `title`; a merge conflict replaces `title` with `t('ui.mergeTitle', {title})`. The board and every log line read `title` directly.

The user decided (issue #38, 2026-10-11): ticket titles follow the current language; log lines keep the language they were written in; saves without the new field show their stored title. Saves store `S.issues` as JSON, and jobs point at the same ticket objects.

## Goals / Non-Goals

**Goals:**

- Ticket titles on the board follow the current language immediately after a switch, for every kind of ticket generated from the pools.
- Log lines written after a switch name tickets in the new language.
- No change to random draws, game numbers, GA events or save structure version.

**Non-Goals:**

- Re-translating log lines or the stored morning report.
- Re-translating tickets from saves written before this change.
- Changing pool contents, sizes or order; changing the merge prefix wording.

## Decisions

### Store the title pool position on the ticket

Each ticket generated by `makeIssue` gets a `src` object `{k, g, i}`: `k` the technology line key, `g` the pool group (`'1'`–`'5'`, `'trap'`, `'research'`, `'inc'`), `i` the index in that pool. Split parts made by `splitResearch` get `{k, g:'research', i, p}` copied from the original plus `p` = 0 or 1 for the part. Merge-conflict tickets keep their `src` and are recognised by the existing `merge:true` flag.

Alternative considered: store a dictionary key per title (for example `pool.laravel.1#3`) as a string. Rejected: the object is just as small, needs no parsing, and keeps research parts explicit.

Alternative considered: make `title` a getter. Rejected: tickets are plain objects saved with `JSON.stringify`, and a getter would not survive the save.

### Keep the stored title string as the fallback

`title` is still written at generation (and still rewritten with the merge prefix on a conflict) in the language current at that moment. It is used only when the ticket has no `src` (saves from before this change, test fixtures built by hand) or when the `src` position no longer resolves to a non-empty string in the current dictionary (a future dictionary edit shrinks a pool). This keeps old saves loading without a `SAVE_VER` bump and keeps existing tests that read `title` meaningful.

Alternative considered: bump `SAVE_VER` and drop the `title` field. Rejected: the user chose to keep old saves playable with their stored titles.

### One display title function, issueTitle

`issueTitle(is)` in `public/js/state.js` (next to `makeIssue`) returns the display title:

1. If `is.src` resolves: the pool entry is a string for groups `1`–`5`, `trap`, `inc`; for `research` it is `entry.t`, or `entry.parts[p]` when `p` is present.
2. If it resolved and `is.merge` is true: `t('ui.mergeTitle', {title: <resolved>})`; if it resolved and not merged: the resolved string.
3. Otherwise: `is.title` unchanged (an old merge ticket's stored title already carries its prefix).

The pool is read with `tl('pool.<k>.<g>')`, so a key missing from the current language falls back to zh-TW like every other lookup.

### Log lines and screen read issueTitle at the moment of use

Every place that shows a ticket title or writes one into a log line or a message calls `issueTitle` instead of reading `title`: ticket cards, background agent rows and the dispatch panel header in `public/js/view.js`; dispatch, result, cancel, conflict, failure, manual work, evaluation, rescope, research, split, overdue and outsourced-overdue log lines in `public/js/actions.js`. A log line is still a finished string, so it keeps the language current when it was written.

### Draw the pool index with the same random calls

`makeIssue` draws the index with `rnd(pool.length)` exactly where `pick(pool)` draws today (same order: trap telltale coin, then the index; the research draw stays after every existing draw and only when `RESEARCH_RATE > 0`). `pick` is `a[rnd(a.length)]`, so the sequence of `Math.random` calls is identical and fixed-seed output does not change.

## Implementation Contract

**Behavior:** after a language switch, every queued ticket generated by this version shows its title in the new language on its card, in a background agent row and in the dispatch panel header; merge-conflict tickets show the new language prefix and inner title; switching back restores the original language. Log lines already written are unchanged; log lines written after the switch use the new language. Tickets without `src` show their stored `title` in every language.

**Data shape:** ticket object gains `src: {k: string, g: '1'|'2'|'3'|'4'|'5'|'trap'|'research'|'inc', i: integer, p?: 0|1}`. `title` (and research `parts`) are still stored. `SAVE_VER` unchanged; `readSave` validity rules unchanged.

**Interface:** `issueTitle(is) → string`, exported from `public/js/state.js`.

**Failure modes:** an unresolvable `src` (unknown stack, group, index or part) silently falls back to `title`; no error is thrown and nothing is logged.

**Acceptance:** new assertions in `tools/check/localization.test.js` cover the success criteria in the proposal (normal, trap, incident, outsourced, research and both split parts, merge-conflict, old-save fallback, log lines before and after a switch); `node tools/check.js` passes; `SIM_N=100 SIM_SEED=101 node tools/sim.js` and `SIM_INVEST=1 SIM_N=100 SIM_SEED=101 node tools/sim.js` print byte-identical output compared with the parent commit.

**In scope:** `makeIssue`, `splitResearch`, the merge-conflict branch of `settle`, `issueTitle`, title reads in `public/js/view.js` and `public/js/actions.js`, the `localization` spec, `docs/DESIGN.md` (多語系 section and the 對話中的需求 list).

**Out of scope:** morning report text, GA events, rules modal text, pool contents, simulator behaviour.

## Risks / Trade-offs

- [A future dictionary edit reorders a pool] → tickets in an in-progress save would show a different title at the same index; numbers are unaffected. Pools are documented as "same number and same order in every language"; DESIGN.md will add that reordering existing pool entries changes titles of saved tickets.
- [A new place reads `is.title` directly and misses the switch] → `tools/check/localization.test.js` adds a full switch scenario that checks the board HTML after switching, so a missed screen read shows up as Chinese text in English mode.
- [Save grows by a small object per ticket] → a few dozen bytes per queued ticket; the measured month-end save is about 45k–60k characters, far from the localStorage limit.
